# AgentLedger 部署形态基线与预检

- 文档版本：v1.0
- 更新时间：2026-03-08
- 目标：为 `多环境 / 多集群 / SaaS 多租户` 提供一份当前仓库可落地的部署基线、配置矩阵与预检入口。

## 1. 适用范围与边界

1. 本文档覆盖当前仓库已经具备实现入口的服务与配置：
   - `apps/control-plane`
   - `apps/web-console`
   - `services/integration`
   - `services/governance`
   - `services/puller`
   - `services/archiver`
2. 本文档是“部署基线”，不是完整 IaC 或 Helm 交付。
3. `SaaS 多租户` 当前仍以应用层租户隔离为主，本文只定义推荐拓扑、配置边界与预检方式，不宣称已具备完整租户专属控制面编排能力。

## 2. 部署形态基线

| 形态 | 适用场景 | 最小组件 | 推荐隔离边界 | 归档建议 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `private-single` | 单租户私有化起步、PoC、小规模内部生产 | `control-plane + web-console + governance + integration + puller + archiver + PostgreSQL + NATS` | 单环境、单集群、单数据库实例 | `ARCHIVE_MODE=local` 或 `hybrid` | 起步成本最低，适合先完成采集、治理、审计、归档主链路。 |
| `multi-env` | 企业私有化标准交付 | `dev / staging / prod` 三环境，各自独立 `PostgreSQL + NATS` | 环境隔离优先；至少 `staging/prod` 独立数据库与消息总线 | `ARCHIVE_MODE=hybrid` | 当前最推荐的企业部署基线。 |
| `saas-multi-tenant` | 共享控制面的 SaaS 场景 | 共享 `control-plane/web-console`，独立或共享 `integration/governance/puller/archiver` | 租户隔离 + 行级权限 + 审计边界；关键数据与归档建议按租户前缀/桶分层 | `ARCHIVE_MODE=object` 或 `hybrid` | 适合先用共享控制面跑通，再按大客户逐步扩展专属归档与独立集群。 |

## 3. 样例配置矩阵

### 3.1 共用最小变量

| 变量 | `private-single` | `multi-env` | `saas-multi-tenant` | 说明 |
| --- | --- | --- | --- | --- |
| `DATABASE_URL` | 必填 | 必填 | 必填 | 当前生产部署默认要求 PostgreSQL。 |
| `NATS_URL` | 必填 | 必填 | 必填 | governance / integration / ingestion-gateway 等事件链路共用。 |
| `CONTROL_PLANE_BASE_URL` | 必填 | 必填 | 必填 | integration 回调与对外控制面地址。 |
| `INTEGRATION_CALLBACK_SECRET` | 必填 | 必填 | 必填 | integration 与 control-plane 必须一致。 |
| `ARCHIVE_MODE` | `local/hybrid` | `hybrid` | `object/hybrid` | 与归档落盘和对象存储能力绑定。 |
| `PULLER_BASE_URL` | 建议配置 | 建议配置 | 建议配置 | 启用 `sessions/search -> puller sync-now` 时建议显式配置。 |

### 3.2 形态样例

#### `private-single`

```dotenv
APP_ENV=production
DATABASE_URL=postgres://agentledger:agentledger@127.0.0.1:5432/agentledger?sslmode=disable
NATS_URL=nats://127.0.0.1:4222
CONTROL_PLANE_BASE_URL=https://agentledger.internal.example.com
INTEGRATION_CALLBACK_SECRET=replace-with-shared-secret
PULLER_BASE_URL=http://puller.service.local:8086

INTEGRATION_CHANNELS=webhook,email
INTEGRATION_WEBHOOK_URL=https://hooks.internal.example.com/agentledger
INTEGRATION_EMAIL_SMTP_HOST=smtp.internal.example.com
INTEGRATION_EMAIL_SMTP_PORT=587
INTEGRATION_EMAIL_SMTP_USER=agentledger
INTEGRATION_EMAIL_SMTP_PASS=replace-with-smtp-pass
INTEGRATION_EMAIL_FROM=alerts@example.com

ARCHIVE_MODE=local
ARCHIVE_LOCAL_ROOT=/data/agentledger/archive/raw
```

#### `multi-env`

```dotenv
APP_ENV=staging
DATABASE_URL=postgres://agentledger:agentledger@postgres.staging.svc.cluster.local:5432/agentledger?sslmode=disable
NATS_URL=nats://nats.staging.svc.cluster.local:4222
CONTROL_PLANE_BASE_URL=https://agentledger.staging.example.com
INTEGRATION_CALLBACK_SECRET=replace-with-shared-secret
PULLER_BASE_URL=http://puller.staging.svc.cluster.local:8086

INTEGRATION_CHANNELS=webhook,ticket
INTEGRATION_WEBHOOK_URL=https://hooks.staging.example.com/agentledger
INTEGRATION_TICKET_WEBHOOK_URL=https://tickets.staging.example.com/api/agentledger

ARCHIVE_MODE=hybrid
ARCHIVE_LOCAL_ROOT=/data/agentledger/archive/raw
ARCHIVE_OBJECT_PROVIDER=s3
ARCHIVE_OBJECT_BUCKET=agentledger-staging-archive
ARCHIVE_OBJECT_PREFIX=staging/archive/raw
ARCHIVE_S3_REGION=ap-southeast-1
```

#### `saas-multi-tenant`

```dotenv
APP_ENV=production
AUTH_DISABLE_LOCAL_LOGIN=true
DATABASE_URL=postgres://agentledger:agentledger@postgres.prod.svc.cluster.local:5432/agentledger?sslmode=disable
NATS_URL=nats://nats.prod.svc.cluster.local:4222
CONTROL_PLANE_BASE_URL=https://control.agentledger.example.com
INTEGRATION_CALLBACK_SECRET=replace-with-shared-secret
PULLER_BASE_URL=http://puller.prod.svc.cluster.local:8086

INTEGRATION_CHANNELS=webhook,incident,ticket
INTEGRATION_WEBHOOK_URL=https://hooks.agentledger.example.com/events
INTEGRATION_INCIDENT_WEBHOOK_URL=https://incident.agentledger.example.com/webhook
INTEGRATION_TICKET_WEBHOOK_URL=https://ticket.agentledger.example.com/webhook

ARCHIVE_MODE=object
ARCHIVE_OBJECT_PROVIDER=s3
ARCHIVE_OBJECT_BUCKET=agentledger-saas-archive
ARCHIVE_OBJECT_PREFIX=shared/archive/raw
ARCHIVE_S3_REGION=ap-southeast-1
```

## 4. 多环境 / 多集群建议

### 4.1 最小环境切分

| 环境 | 目标 | 推荐要求 |
| --- | --- | --- |
| `dev` | 本地联调、接口演进 | 允许本地 `PostgreSQL/NATS`，允许 `ARCHIVE_MODE=local` |
| `staging` | 发布前联调、真实链路回归 | 与 `prod` 保持同类外部依赖，建议独立 `PostgreSQL/NATS` |
| `prod` | 正式运行 | `CONTROL_PLANE_BASE_URL` 走 `https`，归档建议 `hybrid/object` |

### 4.2 多集群建议

1. `control-plane/web-console` 与 `governance/integration/puller/archiver` 可按“控制面 / 数据面”拆分部署。
2. `staging/prod` 至少独立 `DATABASE_URL` 与 `NATS_URL`，避免环境串扰。
3. 若启用跨服务真实回归，建议预留一套 `staging` 专用 PostgreSQL 与 NATS，专门执行 `governance -> integration -> downstream` 冒烟。

## 5. SaaS 多租户建议

1. 当前代码基线已支持资源级 tenant 隔离与审计隔离，但不等于完整“租户专属控制面编排”。
2. 共享控制面基线建议：
   - `AUTH_DISABLE_LOCAL_LOGIN=true`
   - 默认启用对象归档或混合归档
   - `CONTROL_PLANE_BASE_URL` 统一走公网 `https`
3. 大客户可在归档层先做分桶或前缀隔离，再逐步演进到独立对象存储或独立集群。

## 6. 预检与 Smoke 入口

### 6.1 部署预检

当前仓库新增一个独立预检脚本：

```bash
# 预检按能力 profile 执行，不再按“部署形态名”执行。
# 若环境变量中包含 localhost/127.0.0.1 等本地地址，请追加 --allow-local。
bun run ./scripts/check-deployment-baseline.ts --profile governance --env-file ./.env
bun run ./scripts/check-deployment-baseline.ts --profile integration --env-file ./.env

# CI / release 门禁场景（主要校验真实 E2E 数据库配置是否可用）
bun run ./scripts/check-deployment-baseline.ts --profile release-gate
```

脚本职责：

1. `release-gate`：校验发布门禁所需的 `GOV_E2E_DATABASE_URL` 是否存在且为可用的 PostgreSQL 连接串。
2. `governance`：校验 `NATS_URL / DATABASE_URL` 与治理调度相关变量的合法性。
3. `integration`：校验 `NATS_URL / CONTROL_PLANE_BASE_URL / INTEGRATION_CALLBACK_SECRET`，并按 `INTEGRATION_CHANNELS` 自动补充校验对应 webhook / SMTP 等通道配置；integration 当前不强依赖 `DATABASE_URL`（见 `docs/13-环境变量参考.md`）。
4. 默认禁止 loopback/localhost 等本地地址；如需本地演练请显式使用 `--allow-local`。

### 6.2 文档化 Smoke 入口

推荐按形态执行：

| 形态 | 预检 | 最小 smoke |
| --- | --- | --- |
| `private-single` | `bun run ./scripts/check-deployment-baseline.ts --profile governance --env-file ./.env --allow-local` + `bun run ./scripts/check-deployment-baseline.ts --profile integration --env-file ./.env --allow-local` | `bun run smoke:fr505` |
| `multi-env` | `bun run ./scripts/check-deployment-baseline.ts --profile governance --env-file ./.env.staging` + `bun run ./scripts/check-deployment-baseline.ts --profile integration --env-file ./.env.staging` | `bun run smoke:fr505` + `GOV_E2E_DATABASE_URL=... bun run test:e2e-governance-integration-downstream` |
| `saas-multi-tenant` | `bun run ./scripts/check-deployment-baseline.ts --profile governance --env-file ./.env.prod` + `bun run ./scripts/check-deployment-baseline.ts --profile integration --env-file ./.env.prod` | `bun run smoke:fr505` + `GOV_E2E_DATABASE_URL=... bun run test:e2e-governance-integration-downstream` |

## 7. 当前遗留边界

1. 本文档补的是“部署基线”，不是 Helm/Terraform/多集群 IaC 成品。
2. 当前仓库还没有：
   - 完整多环境目录结构与部署资产
   - 多集群流量治理脚本
   - SaaS 专属控制面编排与租户级独立资源调度
3. 因此，部署形态线当前应以“文档基线 + 预检 + 现有 smoke 入口”为交付边界。
