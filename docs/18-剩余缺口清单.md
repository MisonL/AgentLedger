## 4. 建议实施顺序

1. 第一批：quality 高级版预测与建议、replay 实验室完全体
   - 理由：已有基础能力与工作台，适合在现有 API / 控制台上逐步迭代

2. 第二批：SCIM / SAML / MFA / 风险登录、DLP 深化
   - 理由：牵涉身份体系和合规域，跨模块改动较大，适合单独立项

3. 第三批：MCP 企业编排深化
   - 理由：核心编排状态机、动态条件与治理页基础工作台已打通，后续更适合作为“深化体验与企业规则库”的连续增强，而非首批补缺

4. 第四批：Store-and-Forward、本地持久队列、远程配置、Updater、静默安装、多环境多集群部署
   - 理由：属于企业 C/S 与平台形态长期蓝图，设计与交付成本最高，应避免与当前治理主线混做
